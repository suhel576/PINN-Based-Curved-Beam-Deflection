# PINN-Based Deflection Analysis of a Curved Beam

A PyTorch implementation of a Physics-Informed Neural Network (PINN) for estimating the deflection profile of a simply supported beam subjected to a uniformly distributed load (UDL).

**Important scope note:** The current code solves the one-dimensional Euler–Bernoulli beam differential equation and introduces curvature through a heuristic load correction factor. It is therefore a *curvature-adjusted beam approximation*, not a complete curved-beam theory formulation. A rigorous curved-beam model would require the appropriate curved-beam governing equations, geometry, and boundary conditions to be derived and implemented.

## 1. Problem considered

The implementation considers a beam of span \(L\), flexural rigidity \(EI\), and uniformly distributed load \(q\). The PINN approximates the transverse deflection \(w(x)\).

The governing equation implemented in the code is:

\[
EI\frac{d^4w}{dx^4}=q_{\mathrm{eff}},
\]

or

\[
\frac{d^4w}{dx^4}-\frac{q_{\mathrm{eff}}}{EI}=0.
\]

The code defines the effective load as:

\[
q_{\mathrm{eff}}=q\left(1+0.15\kappa L\right),
\]

where \(\kappa\) is the curvature parameter. This correction is an empirical assumption in the supplied implementation; it is not derived from a standard curved-beam formulation.

### Boundary conditions

For a simply supported beam, the code imposes:

\[
w(0)=0,\qquad w(L)=0,
\]

\[
w''(0)=0,\qquad w''(L)=0.
\]

The zero second-derivative conditions correspond to zero bending moment at the two ideal simple supports under the Euler–Bernoulli assumptions.

## 2. PINN methodology

The neural network takes the beam coordinate \(x\) as input and predicts deflection \(w(x)\). The input is normalised internally by the span \(L\).

The network architecture is:

- Input layer: 1 neuron
- Hidden layers: 3 layers, 20 neurons each
- Activation: `tanh`
- Output layer: 1 neuron (predicted deflection)
- Weight initialisation: Xavier normal

PyTorch automatic differentiation computes the derivatives up to the fourth order required by the governing differential equation.

### Loss function

The total objective combines the physics residual and boundary-condition penalties:

\[
\mathcal{L}=\mathcal{L}_{\mathrm{physics}}+
\lambda_{\mathrm{BC}}\mathcal{L}_{\mathrm{BC}}.
\]

The physics loss is:

\[
\mathcal{L}_{\mathrm{physics}}=
\frac{1}{N_c}\sum_{i=1}^{N_c}
\left(w_\theta''''(x_i)-\frac{q_{\mathrm{eff}}}{EI}\right)^2.
\]

The boundary loss penalises violations of the four simply supported conditions:

\[
\mathcal{L}_{\mathrm{BC}}=
w_\theta(0)^2+w_\theta(L)^2+
w_\theta''(0)^2+w_\theta''(L)^2.
\]

The implementation uses the Adam optimiser with a step learning-rate scheduler.

## 4. Analytical comparison

The code also computes the classical simply supported straight-beam solution under UDL:

\[
w(x)=\frac{q}{24EI}x\left(L^3-2Lx^2+x^3\right).
\]

The maximum midspan deflection for the straight beam is:

\[
w_{\max}=\frac{5qL^4}{384EI}.
\]

A second comparison curve is generated by multiplying the straight-beam analytical result by the same heuristic curvature factor:

\[
w_{\mathrm{adjusted}}(x)=
w_{\mathrm{straight}}(x)(1+0.15\kappa L).
\]

This second curve is only a curvature-adjusted estimate based on the code's assumption. It should not be presented as an exact analytical solution for a curved beam.

## 6. Installation and execution

### Requirements

- Python 3.9 or later
- PyTorch
- NumPy
- Matplotlib

Create and activate a virtual environment (recommended):

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

macOS/Linux:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Run the project:

```bash
python curved_beam_pinn.py
```

The script prints the predicted and comparison deflections, displays the deflection and loss plots, and saves the figure as `pinn_curved_beam.png` in the current working directory.

## 7. Results and interpretation

After running the script, record the actual console output and inspect the generated plot. In particular, compare:

## 8. Modelling assumptions and limitations

- The implemented differential equation is the Euler–Bernoulli straight-beam equation.
- Curvature affects the calculation only through the heuristic multiplier \(1+0.15\kappa L\) applied to the load.
- The code does not explicitly model curved-beam geometry, radial/hoop stresses, or a curved-beam coordinate formulation.
- The analytical solution is for a simply supported straight beam under UDL.
- The curvature-adjusted analytical curve is a scaled straight-beam solution, not an independently derived curved-beam analytical solution.
- The training uses a fixed set of uniformly spaced collocation points; the code does not currently report a held-out residual or a formal error norm against a validated curved-beam benchmark.
- The boundary and physics losses have different physical dimensions and are combined with a manually selected weight. Loss scaling and nondimensionalisation may improve training robustness.
- PINN performance should be assessed against a trusted analytical or numerical reference before using results for engineering design.

## 9. Possible future improvements

- Derive and implement a governing equation appropriate to the actual curved-beam geometry and loading.
- Introduce nondimensional variables and scale the loss terms.
- Compare with a finite-element model or a validated curved-beam analytical solution.
- Conduct a parameter study over span, flexural rigidity, load, and curvature.
- Report relative error, maximum absolute error, and boundary-condition residuals.
